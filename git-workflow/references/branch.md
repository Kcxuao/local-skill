# Branch

开始新的独立开发任务时，在修改代码前准备任务分支；同一任务及其附带修改复用已有分支。只读分析不创建分支。

## 分支约定

- 名称采用 `<type>/<english-kebab-case>`，例如 `feat/user-auth`、`fix/order-amount`；类型沿用 Commit 约定：`feat`、`fix`、`init`、`refactor`、`perf`、`docs`、`test`、`chore`、`build`。
- 根据任务语义生成简洁名称，不强制日期或编号。用户指定名称时优先遵循。
- 基础分支优先遵循用户指令及项目约定；否则参考仓库默认开发分支（如 `main`、`develop`）。存在明确功能依赖时，可基于对应功能分支。无法判断时询问，不盲目从当前功能分支派生。

## 执行流程

1. **识别任务**：结合对话、当前分支与 Git 历史判断是否为新的独立任务。新任务创建分支；同一任务继续使用原分支。
2. **检查状态**：确认仓库、当前分支、工作区和已有分支。若创建或切换前存在未提交修改，停止并让用户决定；不自动 Commit、Stash 或使用 Worktree。继续在当前任务分支开发无需切换。
3. **更新引用**：创建分支前，存在 Remote 时先 `git fetch`，优先选择最新且适用的远程基础分支；不自动 Pull、Merge 或更新本地基础分支。Fetch 失败或没有 Remote 时，若本地基础分支明确则继续并提示可能不是最新代码，否则询问。
4. **处理重名**：检查本地及远程同名分支。同一任务复用（仅远程存在时创建本地跟踪分支）；不同任务另取语义化名称；无法确认任务归属时询问，不覆盖已有分支。
5. **创建与核验**：从确定的基础分支创建并切换到本地任务分支，核验分支名称和起点后开始开发。不自动 Push。

## 完成与例外

- 功能完成后保留当前分支，不自动切换、合并或删除；只有用户明确要求才推送远程。
- 本地与远程基础分支分叉且无法安全确定起点时先询问，不丢弃本地提交。
- 当前目录不是 Git 仓库时提示用户，不自动执行 `git init`。
